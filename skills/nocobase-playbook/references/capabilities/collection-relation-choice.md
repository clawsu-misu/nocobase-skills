# 表类型与关系选型判据（Collection & Association Selection）

> 一句话：按结构选表类型、按语义选关系基数，多对多一律用中间表。

---

## R — 原文（Reading）

> 请尽可能使用中间表来建立标准的多对多关系，避免使用该种关系类型。
>
> — 《NocoBase 官方文档（中文版）》, `data-sources/field-m2m-array/index.md`

---

## I — 方法论骨架（Interpretation）

建模粒度上有三条判据：①按业务对象的结构特征选表类型（层级→树表、时间范围事件→日历表、已有 view→视图表、公共字段共享→继承表）；②按「当前记录要看目标几条」选关系方向与基数（多对一/一对多/多对多/一对一）；③多对多落地优先建中间表，不用数组字段。

---

## A1 — 素材中的应用（Past Application）

工单分类用树表解决「分类还要分子分类」（tutorials/v2/02）；知识库文档库用树表（v1/09）；选课用中间表（m2m/index.md）；资产表用继承表把公共字段提到父表（inheritance-collection.md）。

---

## A2 — 触发场景（Future Trigger）★

### 用户会在什么情境下需要这个能力？

1. 当需求出现「分类要能加子分类」时，立刻想到树表而不是再建一张表
2. 当多对多关系还要存额外字段（如选课的分数）时，必须用中间表
3. 连接数据库视图或 SQL 表之前，先确认能给出稳定的记录唯一键。

### 语言信号（用户话里出现这些就应激活）

- 「分类要能加子分类」（树表信号）
- 「多对多还要存额外字段」（必须中间表）
- 「多个用户属于多个部门」（基数判断）
- 「接了个数据库视图，筛选后数据乱了」（记录唯一标识问题）

### 与相邻能力的区分

- 与 `data-model-first` 的区别：先有「有哪些业务对象」才能谈关系；本能力是建模第二步，不负责「要不要建系统模型」。
- 与 `main-vs-external-datasource` 的区别：本能力管「新建的表用什么类型」，主库/外部库决策管「这张表建在哪一侧」。

### 同一来源内的相关能力

- depends-on：`data-model-first`
- contrasts-with：`main-vs-external-datasource`
- composes-with：—

## E — 可执行步骤（Execution）

1. **判断业务对象结构特征 → 选表类型（无特殊结构就用普通表）**
   - 完成标准：每个业务对象都判定了结构特征，表类型的选择有理由可以陈述。

2. **判断「当前记录看目标几条」→ 选关系类型与方向**
   - 完成标准：每条关系都写明了「当前记录看目标几条」，方向与基数无歧义。

3. **多对多一律建中间表；数组型多对多只在既有表结构无法改动时使用**
   - 完成标准：多对多全部落到中间表；若有例外，已记录「既有表结构无法改动」的具体原因。

4. **视图表 / SQL 表：先配稳定的 Record unique key，绝不用 row_number() 这类会漂移的值**
   - 完成标准：视图表 / SQL 表的 Record unique key 已确认是稳定业务值，不依赖排序或行号。

5. **树表：确保数据里不存在父子循环，父子关系字段不要改作他用**
   - 完成标准：树表数据经检查不存在父子循环，父子关系字段未被挪作他用。

## B — 边界（Boundary）★

### 不要在以下情况使用此能力

- 数组型多对多非常规：只有 PostgreSQL 支持用目标表字段过滤源表，其他数据库能力受限。
- 外部数据库只能建普通表与视图表；继承/文件/评论/日历/表达式/树/SQL 表仅主库支持。
- 加密字段加密后仅支持「等于、不等于、存在、不存在」四种筛选，别指望模糊匹配。

### 素材中警告的失败模式

- **用数组字段做多对多** → 后果：能力受限，非 PostgreSQL 无法用目标表字段过滤；正确做法：用中间表建标准多对多
- **用 row_number() 当记录唯一键** → 后果：排序或筛选一变，区块/权限/工作流定位全部失效；正确做法：用稳定业务 ID 或多字段组合

### 容易混淆的邻近方法论

- `data-model-first`：先有「有哪些业务对象」才能谈关系；本能力是建模第二步，不负责「要不要建系统模型」。
- `main-vs-external-datasource`：本能力管「新建的表用什么类型」，主库/外部库决策管「这张表建在哪一侧」。
