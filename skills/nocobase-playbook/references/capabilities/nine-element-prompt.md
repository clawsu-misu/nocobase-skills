# 提示词九要素（Nine-Element Prompt Formula）

> 一句话：先说清「是谁、做什么、怎么做、做到什么标准」，再谈限制。

---

## R — 原文（Reading）

> 记住：先告诉它怎么做对（正面引导），再约束它别做错（适度限制）。
>
> — 《NocoBase 官方文档（中文版）》, `ai-employees/configuration/prompt-engineering-guide.md`

---

## I — 方法论骨架（Interpretation）

提示词 = 起名 + 双重指令 + 模拟确认 + 反复强调 + 强制规则 + 背景信息 + 正向激励 + 参考示例（+ 反面示例）。结构上按「背景 + 任务」分层：背景长期稳定（是谁/风格/能力），任务按需切换（做什么/指标/范围），超过 1000 字符用 XML 标签分区。比例纪律：正面引导约占 80%、限制性约束约 20%，避免一上来就把 AI 写死。

---

## A1 — 素材中的应用（Past Application）

NocoBase 给出的量化区间：基础员工提示词 500–800 字符，复杂场景 800–1500 字符，超过 2000 字符视为过载；关键要求用 MUST / ALWAYS / NEVER 立边界并重复 2–3 次。

---

## A2 — 触发场景（Future Trigger）★

### 用户会在什么情境下需要这个能力？

1. 写任何 Agent 的 system prompt 时都可套这个结构
2. 发现提示词越加越长但效果没提升时，先做减法再补示例
3. 「一上来堆禁止项」是新手最典型的问题，用 80:20 比例自查。

### 语言信号（用户话里出现这些就应激活）

- 「提示词该怎么组织」
- 「禁止项写了一堆还是没用」
- 「提示词越加越长，效果没变好」
- 「角色定义和任务描述分不开」

### 与相邻能力的区分

- 与 `ai-employee-two-layer` 的区别：双层设计给出「写在哪一层」，九要素给出「每一层里写哪几样」。
- 与 `skill-orchestration-chain` 的区别：编排链是技能切分，九要素是单个技能内部的话术结构。

### 同一来源内的相关能力

- depends-on：`ai-employee-two-layer`
- contrasts-with：—
- composes-with：`skill-orchestration-chain`

## E — 可执行步骤（Execution）

1. **先写背景层：你是谁、什么风格、具备什么能力**
   - 完成标准：背景层四要素（你是谁 / 风格 / 能力 / 上下文）已写完。

2. **再写任务层：当前要做什么、衡量指标、处理范围**
   - 完成标准：任务层三要素（做什么 / 衡量指标 / 处理范围）已写完。

3. **加强制规则：用 MUST / ALWAYS / NEVER，关键要求重复 2–3 次**
   - 完成标准：强制规则使用 MUST / ALWAYS / NEVER，关键要求重复 2–3 次。

4. **配参考示例（正例优先，反例可选）**
   - 完成标准：已配至少一条正面示例；若有反例也已标注。

5. **控长度：基础 500–800 字符，复杂 800–1500；超 1000 字符用 XML 标签分区**
   - 完成标准：长度在区间内（基础 500–800 / 复杂 800–1500 字符），超 1000 字符的已用 XML 标签分区。

6. **数量自查：技能 3–5 个、任务 5–7 个、正面与负面比例约 80:20**
   - 完成标准：数量自查通过：技能 3–5 个、任务 5–7 个、正面与负面比例约 80:20。

---

## B — 边界（Boundary）★

### 不要在以下情况使用此能力

- 一上来堆禁止项会把 AI 行为写死，降低泛化能力。
- 负面示例不是必须项，缺省不影响可用性。
- 本条的置信度略低于其他条目——它主要出自 NocoBase 单一来源的实践总结，但已在其多名员工配置页中反复出现。

### 容易混淆的邻近方法论

- `ai-employee-two-layer`：双层设计给出「写在哪一层」，九要素给出「每一层里写哪几样」。
- `skill-orchestration-chain`：编排链是技能切分，九要素是单个技能内部的话术结构。
